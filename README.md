# 一个标准 U-Net 分割项目（尽量通俗版）

这是一个"能直接跑起来"的 U-Net 项目：结构是标准 U-Net，代码尽量写得像说话一样直白，
每个关键步骤都有中文注释，适合第一次自己搭分割项目的人。

---

## 一、U-Net 到底在做什么？

U-Net 是 2015 年专门为**医学图像 / 细胞图像分割**提出的网络（论文：
*U-Net: Convolutional Networks for Biomedical Image Segmentation*）。

它的任务可以用一句话说清楚：

> 输入一张图，输出一张**同样大小**的图，图上每个像素都回答"我是不是目标"。

比如细胞分割：输入显微镜照片，输出黑白掩码，白色是细胞、黑色是背景。

### 为什么叫 U-Net？

因为网络结构画出来像个字母 U：

```
输入 (128x128x3)
   |                                                        （左边：一路缩小）
 [32]  -------------------------- 跳连 --------------------------  [32]
   |                                                              |
 [64]  ---------------------- 跳连 ----------------------  [64]
   |                                                        |
 [128] ------------------ 跳连 ------------------  [128]
   |                                                |
 [256] -------------- 跳连 --------------  [256]
   |                                        |
 [512] ----------- 最底部（8x8，特征最抽象）-----------  [512]

                                                        输出 (128x128x1)
```

- **左边（编码器）**：不断卷积 + 池化，图片越来越小，但"看懂"的东西越来越抽象
  （从边缘 → 纹理 → 整个目标）。
- **右边（解码器）**：不断上采样，把图片放大回原尺寸，并给出每个像素的预测。
- **跳连（skip connection）**：右边每放大一步，就把左边**同尺寸**的特征拿过来拼在一起。
  这一步非常关键：深层特征知道"这里有个目标"，浅层特征知道"它的边缘在哪"，
  拼起来才能既分对、又分得细。

没有跳连，上采样后的边缘会糊成一团——这也是 U-Net 相比普通"编码-解码"网络最大的改进。

> 说明：原论文用的是 572×572 输入、不带 padding 的卷积（每层会缩小 4 个像素），
> 并且只在最底部用了 Dropout。本项目的写法是现在更常见的版本：same padding
> （尺寸只由池化改变）、每层都加 BN、输入边长取 16 的倍数。
> 两者的 U 形结构和"跳连"思想是完全一致的。

## 二、项目文件说明

```
unet_project/
├── config.py       所有参数（图片大小、batch、学习率……）都在这
├── unet.py         U-Net 网络结构，最核心的文件
├── dataset.py      读图片 + 读掩码；还能自动生成演示数据
├── train.py        训练脚本
├── predict.py      用训练好的模型做预测、画对比图
├── prepare_dsb2018.py  一键下载并整理 DSB2018 细胞核数据
├── requirements.txt
└── data/           数据（第一次运行 train.py 会自动生成演示数据）
```

每个文件都很短，建议按 `unet.py → dataset.py → train.py → predict.py` 的顺序读。

## 三、怎么运行

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

需要 Python 3.9 以上。有 NVIDIA 显卡的话，装 CUDA 版 PyTorch 会快很多；
没有也能跑，只是慢一点（本项目演示数据在 CPU 上几分钟就能训练完）。

### 2. 先检查一下网络

```bash
python unet.py
```

应该看到：

```
输入形状: (2, 3, 128, 128)
输出形状: (2, 1, 128, 128)
参数量: 7.763041 M
```

输入输出长宽一样，说明网络没写错。

### 3. 训练

```bash
python train.py
```

第一次运行如果没找到 `data/`，会自动生成一份**演示数据**（灰色背景 + 随机白色形状），
所以不用下载任何数据集就能把流程跑通。训练过程中会打印：

```
第  1/10 轮 | 训练 loss 0.8123 | 验证 loss 0.6543 | 验证 Dice 0.4120 | 6.3 秒
...
```

`Dice` 是衡量分割好坏的指标，越接近 1 越好。验证集上 Dice 最高的模型会保存到
`checkpoints/best.pt`。

### 4. 预测

```bash
python predict.py
```

会拿验证集的第一张图做预测，在 `outputs/` 里生成两张图：

- `0000_mask.png`：预测出的黑白掩码；
- `0000_compare.png`：对比图（原图 | 红色叠加 | 预测掩码 | 真实掩码）。

也可以预测自己的图：

```bash
python predict.py 我的图片.jpg
```

## 四、换成自己的数据

只需要按下面的结构放文件，然后重新运行 `python train.py`（`config.py` 里的路径不用改）：

```
data/
├── train/
│   ├── images/   0001.png  0002.png ...
│   └── masks/    0001.png  0002.png ...   <- 文件名必须和原图一模一样
└── val/
    ├── images/   ...
    └── masks/    ...
```

几个注意点：

1. **掩码是黑底白图**：白色（255）= 目标，黑色（0）= 背景。
2. 原图和掩码**同名**，程序靠文件名配对。
3. 图片尺寸不用统一，`dataset.py` 会自动缩放到 `config.IMAGE_SIZE`。
4. 掩码边缘不要有灰色过渡，最好只有 0 和 255 两种值。
5. 如果目标是细胞核这类"一个挨一个"的东西，注意掩码要能分开相邻目标
   （否则网络会把它们连成一片）。

把 `config.py` 里的 `DEMO_COUNT` 之类删掉不影响，数据存在就不会再自动生成演示数据。

### 想直接用公开数据集？已经接好了 DSB2018

```bash
python prepare_dsb2018.py
```

它会自动完成：下载 `stage1_train.zip`（约 83 MB，Broad 官方直链，CC0 授权，
不用 Kaggle 账号）→ 解压 → 把每张图的几十张单核掩码合并成一张二值掩码 →
按 9:1 分成 `data/train`（603 张）和 `data/val`（67 张）。

跑完直接 `python train.py` 就行。注意真实数据比演示数据难，想效果好一点可以：

- `EPOCHS` 改成 30~50；
- `IMAGE_SIZE` 改成 256（细胞核更清晰，但训练更慢）；
- 600 多张图在 CPU 上会比较慢，有 GPU 最好。

原始数据主页：https://bbbc.broadinstitute.org/BBBC038

## 五、参数怎么调（都在 config.py）

| 参数 | 作用 | 建议 |
| --- | --- | --- |
| `IMAGE_SIZE` | 输入图片边长 | 128 起步；显存够可以 256、512。**必须是 16 的倍数** |
| `BATCH_SIZE` | 一次喂几张图 | 8 起步；显存不够改 4 或 2 |
| `EPOCHS` | 训练多少轮 | 演示 10 轮；真实数据一般 30~100 轮，看验证 Dice 是否还在涨 |
| `LR` | 学习率 | 0.001 是 Adam 的常用值；训练不收敛可以试 0.0001 |
| `BASE_CHANNELS` | 第一层通道数 | 32 是"够用又不太重"的折中；标准 U-Net 原版是 64，电脑慢就 16 |

> 为什么 `IMAGE_SIZE` 必须是 16 的倍数？
> 因为网络里池化了 4 次，每次长宽减半，16 = 2×2×2×2。不是 16 的倍数，
> 上采样回来时尺寸就对不上，跳连没法拼接。

## 六、核心代码在讲什么

### 1. 一块"积木"：double_conv

```python
nn.Conv2d(...)   # 3x3 卷积，提取特征
nn.BatchNorm2d   # 批归一化，训练更稳
nn.ReLU          # 激活，让网络能学非线性
# 以上三个连做两遍
```

### 2. 左边：池化缩小

```python
e1 = self.enc1(x)                 # 128x128
e2 = self.enc2(self.pool(e1))     # 64x64
...
```

`MaxPool2d(2)` 每 2x2 个像素取最大值，长宽减半。

### 3. 右边：放大 + 拼接

```python
d4 = self.up4(center)                     # 转置卷积，放大一倍
d4 = torch.cat([d4, e4], dim=1)           # 和左边同尺寸特征拼起来
d4 = self.dec4(d4)                        # 再卷两下融合
```

`torch.cat(..., dim=1)` 就是"跳连"：把通道维拼在一起。拼完通道数翻倍，
所以后面的 `double_conv` 输入通道也相应翻倍。

### 4. 损失函数：BCE + Dice

```python
loss = bce(logits, masks) + dice_loss(logits, masks)
```

- **BCE**（二元交叉熵）：逐个像素判断对错，是最基础的分类损失。
- **Dice 损失**：直接优化"预测区域和真实区域的重合度"，对前景少的分割任务更友好。

两个加起来通常比单用一个更稳。

### 5. 训练三件套

```python
optimizer.zero_grad()   # 清空上一步的梯度
loss.backward()         # 反向传播，算每个参数的梯度
optimizer.step()        # 按梯度更新参数
```

## 七、常见问题

**1. 报错 `OMP: Error #15 ... libiomp5md.dll already initialized`**

Windows 上某些库重复加载了 OpenMP。`train.py` / `predict.py` 开头已经加了规避代码；
如果还报，先执行 `set KMP_DUPLICATE_LIB_OK=TRUE` 再运行。

**2. 报错"输入图片的长宽必须是 16 的倍数"**

改 `config.py` 的 `IMAGE_SIZE`，用 128、256、512 这类数。

**3. 内存 / 显存不够**

依次尝试：`BASE_CHANNELS` 改成 16 → `BATCH_SIZE` 改成 4 → `IMAGE_SIZE` 改成 128 或 64。

**4. Dice 一直是 0 或者很低**

- 检查掩码是不是真的黑底白图、文件名有没有配对；
- 检查前景占比是不是太小（比如整张图只有 3 个白点）；
- 学习率太大可以降到 0.0001，轮数加多；
- 数据集太小的话，多加数据比调参数有用。

**5. 训练很慢**

没有 GPU 时属正常。演示数据是为了跑通流程，真实项目建议用 GPU；
也可以先缩小 `IMAGE_SIZE` 和 `BASE_CHANNELS` 做快速实验。

**6. Windows 下 DataLoader 报错**

把 `config.py` 的 `NUM_WORKERS` 保持为 0。

## 八、下一步可以怎么扩展

- **多类别分割**：`num_classes` 改成类别数，损失换成 `CrossEntropyLoss`，预测时取 `argmax`。
- **更强的主干**：把编码器换成预训练的 ResNet34（即 ResNet34-UNet），小数据上提升明显。
- **更多数据增强**：随机旋转、缩放、弹性形变，推荐 `albumentations` 库。
- **更多指标**：IoU、精确率、召回率，比只看 Dice 更全面。
- **导出部署**：`torch.onnx.export` 导出 ONNX，方便在 C++ / 网页端使用。
